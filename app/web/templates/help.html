{{ icon('shield') }} 运行体检

{{ icon('zap') }} 它是怎么工作的（30 秒版）

你（微信 / 飞书 / QQ…）→ 消息渠道→ Gateway 网关→ Hermes Agent→ 模型供应商（AI 大脑）

你在聊天软件里发消息，渠道把它交给常驻后台的 Gateway，Gateway 唤醒 Agent 去干活， Agent 调用模型供应商的 AI 来思考，结果原路发回给你。本控制台管理的就是这整条链路的安装与配置 —— 对应的初始化四步：装 Agent → 配主模型 → 启用渠道 → 启动 Gateway（仪表盘有进度清单）。

{{ icon('book') }} 概念速查

Gateway（网关） 常驻后台的服务，负责收发各渠道消息并驱动 Agent。「启动 Gateway」就是启动它。
模型供应商提供 AI 模型的服务方（GLM / Kimi / OpenRouter…），需要在它官网注册并创建 API Key。
主模型Agent 默认用哪个模型思考和回答，在「模型供应商」里设置。
备选链主模型超时或故障时，按顺序顶上的备用模型列表。
消息渠道你在哪里跟 Agent 聊天：微信、飞书、QQ、Telegram 等 14 个。
工具集允许 Agent 在某个渠道使用哪些工具；对外的渠道建议只给 safe 集合。
记忆系统Agent 跨会话记住信息的地方；内置容量小，大项目可一键切换外置方案。
MCP 服务给 Agent 外挂工具的标准接口（联网搜索、读数据库…），在「MCP 服务」页添加。
技能（Skill）教 Agent 做某类任务的「说明书」包，放在 ~/.hermes/skills/。
插件与 Hook深度定制 Agent 行为的代码扩展；官方安全模型默认禁用，按白名单开启。
白名单（dm_policy）谁可以私聊你的 Agent。建议 allowlist 只放自己，防止陌生人消耗你的额度。
config.yaml / .envHermes 的两份配置文件。密钥等敏感信息只写 .env，控制台永不回显。
